# Админ-панель · проектирование и план · 23 октября 2026

Цель: сотрудник входит в `/admin/`, находит заявку, связывается с гостем и подтверждает, отменяет или завершает визит. Доступ к именам и телефонам — только после входа. Публичная форма сохраняет прежний контракт и не обещает автоматического подтверждения столика.

## Решения

Остаётся текущий стек TypeScript/Vite + Node.js/SQLite. Админка — отдельная HTML-страница с собственными небольшими модулями и стилями. Она использует существующую модель статусов; фреймворк, внешняя авторизация и новые runtime-зависимости не требуются.

Учётная запись создаётся локальной командой `npm run admin:init`, случайный уникальный пароль сохраняется в закрытом файле рядом с базой. Повторный обычный запуск не меняет пароль. В базе хранится только salted scrypt hash. Вход создаёт случайную сессию на восемь часов, её ключ в базе хешируется. Cookie HttpOnly/SameSite=Strict, при HTTPS включается Secure через настройку. Запись требует проверки Origin и CSRF-токена; попытки входа ограничены. Никаких имён, телефонов, паролей или сессий в localStorage.

Список поддерживает поиск по номеру/имени/телефону, статус, диапазон дат визита и страницы по 20 заявок. Счётчики отражают все статусы. Действия: requested → confirmed/cancelled; confirmed → completed/cancelled. Терминальные состояния не переоткрываются. PATCH включает ожидаемый предыдущий статус, чтобы устаревшая вкладка не перезаписала чужое решение. Изменения фиксируются в истории вместе с сотрудником и временем. Смена пароля завершает все сессии.

## Контракты

- GET `/api/admin/session`, POST `/api/admin/login` → `{username, csrfToken}`; POST logout и password; cookie не доступна JavaScript.
- GET `/api/admin/bookings?status=all&q=&dateFrom=&dateTo=&page=1&pageSize=20` → `{items,total,page,pageSize,counts}`.
- GET `/api/admin/bookings/:id` → `{booking,history}`.
- PATCH `/api/admin/bookings/:id`, `{status,expectedStatus}` → `{booking}`; 409 при устаревшем статусе.
- Запись: JSON, правильный Origin, `X-CSRF-Token`; ошибки `{message}`. Без входа 401, чужой Origin/CSRF 403.

## Выполнение и проверка

1. Регрессии четырёх замечаний: сначала воспроизведение, затем доступные имена/нейтральный счётчик, согласование HOST и read-only поддержка старых столбцов.
2. Сервер: сначала тесты отказа без входа/CSRF, затем вход, сессии, фильтры, переходы, история и смена пароля. Отдельные временные базы; настоящие заявки в тестах не используются.
3. Интерфейс: вход, загрузка и пустой список, фильтры, пагинация, подробности, действия и понятные ошибки; мобильная компоновка и клавиатура.
4. Сборка, полный набор автоматических тестов, браузерный сценарий с настоящим API/SQLite, повтор axe-проверки замечаний и независимое ревью.
5. Обновление README/QA и ZIP без базы, локального файла доступа и секретов; создание локального доступа и запуск проверенной версии.

## Особое внимание при проверке

- Одновременные решения из двух вкладок: одно устаревшее действие отклоняется.
- Истечение сессии: сведения о заявках удаляются из интерфейса, нужен повторный вход.
- Сетевой сбой при изменении статуса: интерфейс не утверждает, что решение сохранено, пока не получен ответ; повтор проверяет состояние.
- Необычные имена и пожелания выводятся как текст, без HTML.
- Неверная дата, страница, статус и слишком длинный запрос отклоняются на сервере.

## Запуск

1. Запустите сайт через `START_SITE.cmd` или `npm run open`.
2. Создайте доступ: `npm run admin:init` (для готового архива без node_modules: `node server/admin-init.mjs`).
3. Откройте `http://127.0.0.1:5173/admin/`. Логин и случайный пароль находятся в `data/admin-access.txt`; при другом DATABASE_PATH — рядом с базой. Файл не отдаётся HTTP-сервером и исключён из архива.
4. После первого входа смените пароль через панель. Первоначальный файл больше не содержит действующего пароля после смены. Для восстановления доступа на сервере: `npm run admin:init -- --reset`; старые сессии прекращаются.

Для HTTPS включите `ADMIN_COOKIE_SECURE=true` в `.env` и перезапустите сервер. Для стандартного loopback HTTP оставьте false. Учётная запись одна; альтернативный логин задаётся `--username manager`. Управления ролями нет.

Изменение статуса записывает решение и историю, но не отправляет гостю письмо или сообщение. Вначале сотрудник связывается с гостем. Для просмотра из другой сети требуются собственный сервер и HTTPS; локальный адрес доступен на этом компьютере.

Регрессионные команды: `npm test`, `npm run test:browser`, `npm run test:admin`. Тесты используют отдельные временные базы и вымышленные заявки. Результаты текущей проверки описаны в `docs/QA.md`.
